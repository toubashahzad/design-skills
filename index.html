Your process, in Claude Code.

Three small skills that make Claude collect before it builds, explore without committing, and show you options instead of describing them. Drop them into any repository; they work from the first message.

Install all three

Run it in your project root

npx -y degit toubashahzad/design-skills/.agents/skills/mock-it .claude/skills/mock-it &&
npx -y degit toubashahzad/design-skills/.agents/skills/explore .claude/skills/explore

The skills

/list-it Capture

Collects everything you ask for into a numbered list and builds none of it until you say go. For dictating changes faster than you want them done — the list comes back after every addition, so nothing is lost and nothing starts early.

Changes what Claude does with a request: holds it instead of acting on it. 

npx -y degit toubashahzad/design-skills/.agents/skills/list-it .claude/skills/list-it
/mock-it Show

Renders two to four labelled variants inline in the chat, drawn in the project's own tokens and at the real proportions, each with a one-line trade-off. No artifact to open, no link to follow — you look, you pick.

Changes what an answer looks like: a picture rather than a paragraph describing one. 

npx -y degit toubashahzad/design-skills/.agents/skills/mock-it .claude/skills/mock-it
/explore Think

Opens a second lane beside a running list, for working an idea out before it becomes work. Produces options and trade-offs and nothing else; an outcome joins the list only when you say so.

Changes what undecided means: a place to be unsure that does not leak into the build. 

npx -y degit toubashahzad/design-skills/.agents/skills/explore .claude/skills/explore

One more, kept here as a worked example rather than as something to install. Most of what a skill is worth saying is specific to one codebase, and that is the kind hardest to picture from a generic one.

/case-study Project-specific

Everything a portfolio's case-study pages need: the section model, the four caps that keep a header above the fold, the image conventions that need no code, and a script that reports what a study is currently made of and which of its pictures have no file — a thing no build will ever tell you, because a missing picture renders an empty frame and passes.

Written against one repository and only works there: its script imports that project's TypeScript by path. Read it for the shape, not to run it.

How they work

Two ways in

Type /list-it to start one by hand, or just work — each skill carries a description saying when it applies, and Claude opens it when the moment matches.

A folder and a file

A skill is a directory with a SKILL.md inside: frontmatter naming it, Markdown telling Claude what to do. The commands above drop one into .claude/skills/.

Per project

They live in the repository, so they are version-controlled with the code and everyone who clones it gets them. Nothing is installed globally and nothing phones home.

Yours to change

They are plain Markdown. Open one, rewrite a rule, and the next message follows the new version — no build step, no reload.
